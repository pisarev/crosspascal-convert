# Gemma 3n conversion

This experimental route converts compatible Gemma 3n GGUF files into a native TVM CPU or CUDA library, file-backed parameters and a SentencePiece tokenizer. It reads the architecture and tensor shapes rather than matching model names. Different layer counts, hidden widths, attention layouts, AltUp widths and shared-KV counts are derived from the source. Missing tensors or incompatible shapes are errors.

Text conversion is the first step. A separate vision add-on converts a compatible gemma3nv projector for a CUDA text bundle. Audio, video, other Gemma architectures and Gemma 3n Hugging Face SafeTensors input are not implemented by this backend. GGUF quantized weights are dequantized; comparison with an original unquantized checkpoint is a different experiment. Keep the model's original access rights and license terms. The converter does not download or redistribute weights.

The CPU profile uses FP32 weights. The CUDA profile uses per-row symmetric int8 projection weights, FP32 arithmetic and a native fused dequantizing matrix-vector kernel generated by TVM. Input embedding tables remain in host memory; only selected rows move to the GPU. This is an additional quantization step, not a claim of bit-identical FP32 output. The GPU library executes attention, shared KV, AltUp, LAuReL, feed-forward layers and output projection; it does not delegate inference to PyTorch or Ollama.

## Conversion dependencies

Use the installed Windows x64 converter's TVM 0.26 environment, its compatible LLVM and Windows C++ linker. An additional Python environment is needed for the architecture exporter. The checked combination uses Python 3.11, PyTorch 2.11, Transformers 4.57.6, GGUF 0.19.0, SentencePiece 0.2.1, NumPy, ONNX, protobuf and the normal Transformers dependencies. Set `CROSSPASCAL_GEMMA_PYTHON` to that environment's absolute Python executable before opening the converter. `CROSSPASCAL_GEMMA_PACKAGES` can contain additional package directories separated by semicolons; it is unnecessary in a normally installed environment.

For execution, the TVM Python environment needs NumPy and SentencePiece 0.2.1 for its own Python version. `CROSSPASCAL_GEMMA_RUNTIME_PACKAGES` can point to that runtime package directory. Inference itself does not import PyTorch, Transformers, GGUF or Ollama.

E4B expands to about 25.6 GiB of parameter files. CUDA adds compact projection files; allow another 6 GiB for that checkpoint. Other model sizes need different amounts of storage. The converter checks available memory before starting; 8 GiB of available RAM and commit is its admission floor, not a promise of fast execution. File-backed parameters avoid allocating a second full model, but loading and repeatedly accessing them still benefits from ample physical memory and fast storage. CUDA execution checks free device memory against the actual weights, KV state and a workspace reserve. Insufficient memory is an error, with no implicit CPU fallback.

## Convert in the browser

1. Open the local converter.
2. Paste the full path to the original Gemma 3n GGUF in the model path field. A file does not need a particular model name or extension; its contents identify the architecture.
3. On the first wizard page, expand **Gemma conversion (experimental)**. This separate route does not require the general **Recognise** button.
4. Choose the context capacity. Keep **Detect available device** to detect CUDA automatically, or select CPU or CUDA explicitly. Leave **CUDA architecture** empty to detect this computer, or enter the destination architecture manually. For CPU, keep **generic** unless intentionally compiling for another supported LLVM CPU target.
5. Click **Inspect Gemma checkpoint**. Review the detected architecture, layer count, hidden width and context.
6. Click **Convert Gemma** and wait for its output directory. The source is pinned between inspection and conversion. Changing a selection requires another inspection.

Contexts exposed by the browser are 64, 128, 256, 512 and 1024 tokens. Local attention still uses the window declared by the model. Conversion emits a one-token graph with persistent KV state; it does not repeat a full-prefix computation for each generated token. Both profiles currently process prompt tokens one at a time. Longer prompts therefore increase time to the first response. CUDA compilation requires the converter's compatible CUDA compiler/driver environment. A destination architecture is not tied to a card name; compilation for an architecture does not prove execution on every card with that architecture.

## Run the converted bundle

The Python consumer is `source/pascalvision_convert/gemma3n_runtime.py`. From the matching TVM Python environment:

```text
python source/pascalvision_convert/gemma3n_runtime.py "C:\Models\converted-gemma" --prompt "What is the capital of France? Answer with the city name only."
```

It streams the decoded output and prints a timing/result record. By default it uses Gemma's `user`/`model` chat markers, including for Ollama GGUF files whose template is stored separately. Use `--plain` explicitly for a base model's plain completion. Arbitrary custom chat templates are not executed. `--max-new-tokens 0`, the default, runs until the model's stop token or the compiled context capacity. A positive value sets a manual limit; Ctrl+C stops generation. The prompt and response share the compiled context. A context limit is reported explicitly and is not an unlimited-generation promise. `--result` saves a JSON record. The `Session` class can be retained for repeated requests without remapping the weights; each request gets a fresh KV cache.

The consumer selects CPU or CUDA from the bundle manifest. `GpuSession` keeps compact device weights resident between requests and transfers only embedding rows; each request gets a fresh KV cache. Its result separates weight loading, first-token time, per-token timestamps and device memory. Streaming callbacks receive text after each generated token. The CPU consumer uses versioned DLPack. Both consumers use read-only parameter mappings and return errors for incompatible bundles. Build reports inference as `NOT_CHECKED`; a separate execution is required. GemmaChat and QwenChat now use the shared LanguageModel API; both can inspect and load supported bundles. GemmaChat is verified in Delphi 13.2 and Lazarus 4.8. Extract the release's Gemma runtime asset beside the SDK and follow crosspascal/examples/gemma-chat/README.md.

Use `with GpuSession(bundle) as session:` in an embedding application, or call `close()` after the last request. Calls are serialized on a persistent worker. A session-owned temporary workspace fixes the pinned Windows TVM allocator's failure during thread-local destruction. It replaces only that loaded model library's workspace context slots and restores them at close; it does not modify DLL files, replace the system allocator, reset the device or suppress failures. Opening the same model library twice concurrently in one process is rejected before the context slots can be changed. Reopening after close is supported. The command-line consumer closes automatically on normal exit.

The checked CUDA text profile includes the original E4B GGUF and a synthetic configuration with different width, layers, AltUp and shared-KV settings. The synthetic test crosses a local-attention boundary and compares full output logits with PyTorch using exactly the same compact weights. Fixed E4B questions also match the established source-weight reference. These checks do not establish quality for every checkpoint or prompt. CPU FP32 and CUDA W8A32 are distinct numerical profiles.

## Add images through the converter

1. Obtain the matching Gemma 3n vision projector GGUF under the model's original terms. The text GGUF alone is insufficient.
2. Install `timm==1.0.22` and `onnxsim==0.4.36` in the Gemma conversion Python environment described above. Completed-bundle inference does not need these packages.
3. On the first wizard page, open **Add images to a Gemma 3n bundle (experimental)**. No source-model recognition is needed. Enter the converted CUDA text bundle folder and projector filename.
4. Click **Inspect image support** to check the architecture, projection width, selected files and destination CUDA architecture.
5. Click **Build image bundle**. The text graph is reused. The new independent bundle needs space for the original text bundle plus at least 4 GiB. Source files remain unchanged.
6. Select the new folder in GemmaChat, click **Attach image**, and ask a question. The matching runtime includes Pillow 12.0.0 for image decoding.

The encoder uses timm's MobileNetV5 architecture and MSFA resize/pooling semantics, followed by Gemma 3n projection and normalization. The export shim makes spatial dimensions constant for ONNX. The static fusion adapter is adapted from timm 1.0.22 under Apache-2.0; its attribution and complete license are preserved in the exporter and `licenses/timm-LICENSE.txt`. The remaining original integration uses the project license. No pretrained weights are downloaded implicitly.

Vision parameters are FP32. The compiler replaces constant `Pow(x, 2)` with `x*x` before CUDA lowering: the pinned CUDA fast-math power operation is invalid for negative bases. The equivalent square was checked against PyTorch embeddings. The manifest records preprocessing, dimensions, source identity and hashes. Missing or changed artifacts are rejected.

The verified 768-pixel profile contributes 256 image tokens. Image encoding is separate from reading those tokens through the text decoder, which proceeds one token at a time. An unchanged image reuses its encoded features on a repeated request. Unload releases the session.

## Optional text-parameter reuse during development

`CROSSPASCAL_GEMMA_PARAMETER_CACHE` may identify an existing prepared parameter directory on the same NTFS volume as the output. Reuse requires matching original source SHA-256, complete architecture configuration, parameter mapping, file sizes and every weight hash. Only unchanged parameters are hard-linked; the graph, buffers, tokenizer, manifest and DLL are generated for the new request. Omit the variable for normal first-time conversion. A mismatched cache is rejected, never silently substituted.
